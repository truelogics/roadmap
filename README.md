# Roadmap

## What is this?

The company-wide priority board: what we are building now, next, and later.

## Why does it exist?

So humans and agents share one view of intent and order. Avoids “everything is
urgent” and keeps work moving through clear horizons.

## Who is it for?

- Founders / product / eng leads setting priority
- Engineers picking up work
- Agents that need to know what matters *right now*

## Current status

**Living** — active priorities are maintained in `NOW.md` / `NEXT.md` /
`BACKLOG.md`. Update when priorities shift.

## Roadmap (horizons)

| File | Meaning |
|------|---------|
| [`NOW.md`](NOW.md) | Active work (1–3 items) |
| [`NEXT.md`](NEXT.md) | Committed, not started |
| [`BACKLOG.md`](BACKLOG.md) | Queued, prioritized |
| [`IDEAS.md`](IDEAS.md) | Unprioritized |
| [`MILESTONES.md`](MILESTONES.md) | Major outcomes + dates |
| [`RELEASES.md`](RELEASES.md) | What shipped |

**Now:** Engineering Kernel MVP · RFC-0001 · data model  
**Next:** AI Context Engine · Engineering Rules  
**Backlog:** Agent Runtime · MCP Toolkit · Product Brain

## Contributing

Edit the relevant horizon file and open a PR. Keep `NOW.md` to 1–3 items —
promote from `NEXT.md` / `BACKLOG.md` as work completes. Link RFCs/ADRs when a
priority implies a design decision.
